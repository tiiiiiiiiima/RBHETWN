# Поля DS в 0.16

Полные сцены броска увеличены вдвое, центральная короткая сторона —
36 единиц. Исходные meshes, UV, текстуры, joint/MAT/SRT-анимации
и относительные координаты SetData сохранены. Все восемь полей и
25 расстановок доступны. Границы дополнены близкими проходимыми
треугольниками и предметами; отсечение движущейся геометрии масштабируется.
Мини-карта строит план по исходной статической поверхности. Камера,
масштаб, стартовые позиции и физические параметры остаются ПК-адаптацией.
[Описание 0.16](RELEASE-0.16.md), [источники](ASSET-SOURCES-0.16.md).

# Поля в 0.15

Добавлены исходные G/S, ускорители и трамплины. Используются координаты
и повороты SetData с тем же масштабом/переносом, что у соответствующего
поля. На восьми полях доступны 25 вариантов расстановки. Объекты имеют
свои исходные текстуры, UV и поддерживаемые анимации. SRT-fx16 теперь
имеет правильную единицу 4096. Срабатывания площадок, награды и сброс
предметов адаптированы для ПК; неизвестные типы таблиц не исполняются.

# Арены DS

Источником служит загруженная пользователем Nintendo DS-версия `B6RE` (`BAKUGAN W` в заголовке ROM). Исходный ROM и ZIP не включены в проект, игровые ресурсы или Windows-архив.

В [arena_manifest.json](../assets/ds/arenas/arena_manifest.json) записаны исходные пути NitroFS, SHA-256 каждого файла модели/текстур/анимаций, хеш ROM и архива, версия и хеш конвертера. Импорт содержит **18 групп, 51 исходную 3D-модель и 278 встроенных изображений текстур**; изображения могут повторяться между отдельными GLB. Геометрия содержит 20 353 треугольника.

| Группы | Исходники | Использование |
|---|---|---|
| Pyrus, Aquos, Subterra, Haos, Darkus, Ventus | `Game/Battle/3d/Map/` — основная модель, отдельные фоны, небо и объекты | Выбираемые боевые сцены DS |
| Toy, Anime | `00_Toy`, `anime` | Боевые сцены DS |
| Toythrow, Animethrow | `Toythrow_00`, `animethrow` | Выбираемые поля броска |
| Шесть элементальных полей броска | `*throw_00` и соответствующие фоновые объекты | Выбираемые игровые поля с измеренными статическими столкновениями в 0.11 |
| Парк, стандартный стадион сюжета | `story/map/cut_park`, `cut_standard` | Импортированные сцены; доступны API предпросмотра |

В 0.11 выбор `DS · Pyrus/Aquos/Subterra/Haos/Darkus/Ventus` меняет **боевую сцену и поле броска** на соответствующее исходное окружение. Подмена элементальных полей плоской Toythrow, использовавшаяся в 0.10, снята. Toy использует Toythrow, Anime — Animethrow. Четыре прежние темы остаются доступными.

Для каждой группы измерена реальная центральная горизонтальная поверхность исходной модели. Сцену целиком равномерно масштабируют и перемещают так, чтобы поверхность оказалась на Y=0. Все взаимные положения объектов, геометрия, материалы и UV сохраняются. Границы поля броска проверены в 25 точках на этой поверхности.

В [throw_surface_profiles.json](../assets/ds/arenas/throw_surface_profiles.json) сохранены **1110 локальных треугольников** восьми полей: они измерены по реальным скелетным вершинам исходной неподвижной позы. `scripts/field_surface.gd` использует их для основания и препятствий, проверяет перемещение сферы по отрезку; полёт также проверяет участки кривой. Профиль содержит исходные хеши компонентов и границы адаптированного поля. Дальнее небо и удалённая геометрия, которой сфера не может коснуться, в локальные столкновения не включаются.

Игровые поля показывают неподвижную исходную позу: скелетные анимации окружения остановлены, чтобы видимая геометрия совпадала со статическими поверхностями. Независимый предпросмотр исходника может показывать поддерживаемые движения. Это **статические столкновения ПК по исходной геометрии**, а не код физики DS. Сетка постановки ворот, коэффициенты движения, торможение и отскок остаются адаптацией; движущиеся препятствия и особые игровые механизмы арен пока не восстановлены.

Apicula сохраняет поддерживаемые скелетные NSBCA-анимации. NSBTA/NSBTP-анимации материалов и переключения текстур, а также BMA0/BVA0 не перенесены. Удалены 19 каналов без связанного узла, которые конвертер создавал для неподдерживаемых целей; настоящие каналы движения узлов сохранены. Повторение экспортированных фоновых анимаций в боевой сцене и предпросмотре — адаптация для ПК. Это исходные 3D-ресурсы DS, но полное совпадение с оригинальным игровым процессом и камерой не заявляется.

Воспроизведение импорта из подготовленной NitroFS-папки:

```bash
python3 tools/import_ds_arenas.py /path/to/raw \
  --apicula /path/to/apicula \
  --staging /path/outside/project/arena-nitro \
  --output assets/ds/arenas \
  --inventory /path/to/inventory.json

godot --headless --path . --script res://tools/inspect_ds_arena_geometry.gd \
  -- /absolute/project/assets/ds/arenas /tmp/arena-geometry.json

python3 tools/fit_ds_arenas.py /tmp/arena-geometry.json \
  assets/ds/arenas/arena_manifest.json --project .
```

Измеренный профиль неподвижных столкновений строится отдельно:

```bash
godot --headless --path . --script res://tools/inspect_ds_throw_surfaces.gd \
  -- /tmp/ds-throw-triangles.json

python3 tools/build_ds_surface_profiles.py /tmp/ds-throw-triangles.json \
  --manifest assets/ds/arenas/arena_manifest.json \
  --output assets/ds/arenas/throw_surface_profiles.json
```

`scripts/ds_arena_catalog.gd` предоставляет `make_battle_stage(theme)`, `make_throw_stage(theme)` и `make_source_preview(group_id)`. Поле броска получает метаданные об остановленных исходных анимациях и измеренных статических столкновениях. У боевых сцен есть `ds_far_hint`, рассчитанный по всей геометрии: некоторые исходные пейзажи требуют дальности камеры больше 150 единиц.

Для Pyrus выбран противоположный ракурс: исходный крупный объект перекрывал
карты с прежней камеры. Геометрия и материалы сохранены; управление движением
на DS-полях следует направлению камеры. Это адаптация обзора ПК.
# Арены в 0.14

Работают исходные SRT и MAT0: 31 компонент движения UV и 9 компонентов
цвета/прозрачности, 290 и 92 дорожки соответственно. Отскок и катание
учитывают скорость исходных движущихся треугольников. Прыжок наследует
вертикальную скорость платформы. Q/E переключают четыре ракурса; начало
повторного матча сбрасывает время механизмов и камеру.

Точная DS-физика, особые триггеры, BVA/PAT и исходная камера не
восстановлены; параметры ПК явно описаны в [0.14](RELEASE-0.14.md).
