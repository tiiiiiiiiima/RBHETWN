# Графика интерфейса из предоставленной DS-версии

Ресурсы действительно извлечены из пользовательского архива `Bakugan-DS.zip`
(SHA-256 `4f369e92b78efdbca016a653a1b2638500bf2ecbe1cbd01464043e9e88c9c748`).
NitroFS-инвентарь определяет код игры `B6RE`; ROM в проект и сборку не добавлен.
Полный источник и SHA-256 каждого графического файла сохранены в
`assets/ds/ui_manifest.json`.

Декодированы **446 исходных наборов графики**, включая 219 крупных изображений
карт, 41 набор портретов бакуганов и 18 наборов иконок персонажей. NCE-наборы
содержат 1680 описаний кадров. PNG, отдельные надписи и манифест находятся в
`assets/ds/ui`; имена и подписи дополнительно извлечены из исходных MES-таблиц.
Ориентация изображений сохранена из NCE, без произвольного поворота.

## Фактический формат

В `Game/Battle/Bg`, `Game/Battle/Obj` и `Game/Confrontation` файлы `.bin`
содержат LZ10-потоки без обычных заголовков NCGR/NCLR/NCER:

- NCL: маленький массив DS RGB555; индекс 0 прозрачен.
- NCG: фоновая 8-битная или спрайтовая 4/8-битная графика тайлами 8×8.
- NSC: 16-битные ссылки на тайлы, включая исходные горизонтальные/вертикальные
  отражения. Выводится видимая область экрана DS 256×192.
- NCE: 16-байтный заголовок, 12-байтные записи OAM-частей с явными знаковыми
  координатами, 28-байтные описания кадров, затем секция последовательностей.
  В ROM встречаются шаги номера OBJ1D-тайла 32 и 128 байт. Декодер проверяет
  все ссылки и сохраняет выбранный шаг в манифесте.

Из частей каждого NCE-кадра собраны прозрачные PNG-атласы. Манифест сохраняет
прямоугольник каждого кадра, его размер, исходную точку, длительность и сырые
байты описания. Сами изображения, координаты и отражения декодированы;
аффинные преобразования, масштабирование и воспроизведение последовательностей
DS автоматически не воспроизводятся. Это графические ресурсы, а не копия всей
логики или постановки исходной игры.

## Ресурсы для нового боевого интерфейса

В `ui_manifest.json` ключ `runtime` даёт готовые одиночные PNG через поля
`path`, `frame`, `size`, `source_asset`, `meaning`.

| Ключ | Подтверждённое содержимое |
|---|---|
| `battle` | `BATTLE!` |
| `stand` | `STAND!` |
| `win` | `Victory!` |
| `lose` | `You lost.` |
| `game_start` | `GAME START` |
| `gate_won` | `GATECARD WON!`, получение карты после победы |
| `critical_ko`, `double_stand`, `no_good` | Исходные соответствующие надписи |
| `turn` | Полоска `TURN` |
| `status` | Синяя иконка руки из набора состояния |
| `ability` | Подсказка **`Use an Ability card!`**, не надпись активации |
| `g_frame` | Металлические парные полосы сравнения без встроенных чисел |
| `g_fill_player`, `g_fill_enemy` | Голубая и красная полосы заполнения |
| `vs_icon` | Серебряный значок `VS` |
| `attribute_pyrus`…`attribute_ventus` | Шесть исходных эмблем стихий |
| `digit_0`…`digit_9`, `digit_plus`, `digit_minus` | Оригинальные белые цифры с голубой обводкой, PNG 16×16 |
| `perfect` | `Perfect!` |
| `card_back` | Исходная рубашка карты с логотипом и оранжевой вспышкой |
| `portrait_<specieskey>` | 40 сопоставленных исходных портретов бакуганов, PNG 64×96 |
| `gate_dragonoid`, `gate_leonidas`, `gate_griffon` | Исходные арты соответствующих золотых карт, PNG 96×128 |
| `gate_aquos_vortex`, `gate_the_cliffs` | Исходные арты соответствующих серебряных карт, PNG 96×128 |

Надписи `gate_open`, `draw` и `ability_activate` уверенно не найдены и не
назначены. `GATECARD WON!` нельзя использовать как раскрытие ворот, а `NO GOOD`
как ничью. Отдельная боевая буква `G` не назначена; цифры найдены фактически.

Набор `battle_u` содержит ещё и рамки **S.Power** для специального броска.
Они сохранены в атласе, но не представлены как рамки G-Power обычного боя.

## Имена, подписи карт и варианты портретов

`assets/ds/messages.json` содержит реальные английские MES-записи:
43 имени бакуганов, 213 названий карт и 213 текстов эффектов. Формат — LZ10,
счётчик `uint16`, таблица пар `uint16 offset/length` и 16-битные индексы глифов.
Это **не обычный UTF-16 текст**: английские печатные символы соответствуют
ASCII−32, `0xff84` задаёт пробел, `0xff80` конец записи. Неизвестные управляющие
коды остаются явными, например `<0xff85>`; они не исполняются и не объявляются
правилом игры. Записи сохраняют исходные индексы, байтовые границы и кодовые
единицы, таблицы — исходные SHA-256.

`native_portraits` в UI-манифесте сопоставляет 40 видов, распознанных по
**извлечённым изображениям**, с реальными английскими именами. Это не вывод
названия из номера модели: компактный MES-индекс 2 — Tigrerra, тогда как её
портрет имеет ресурсный номер 004. Связь номера с внутренними исполняемыми
таблицами DS не дизассемблировалась. Дополнительная сверка преобразованных
исходных моделей исправила первоначальное ошибочное сопоставление номера
008 с базовым Preyas: **006 — Preyas** (MES-индекс 4), **007 — Preyas II Angelo**
(полное имя в MES-индексе 41), **008 — Preyas II Diablo** (полное имя в
MES-индексе 42). Runtime-псевдонимы имеют ключи `portrait_preyas`,
`portrait_preyas_ii_angelo` и `portrait_preyas_ii_diablo`. История исправления
записана в `portrait_identity_corrections`. Исходное имя `Fortress` связано с
уже используемым в проекте ключом `fourtress`, само исходное имя сохранено.

У обычных портретов есть шесть первых 256-цветных палитр. Порядок
Pyrus/Aquos/Subterra/Haos/Darkus/Ventus подтверждён видимыми красным, синим,
коричневым, белым, фиолетовым и зелёным вариантами Robotallion. Ссылки на
точные PNG с исходными палитрами доступны через
`native_portraits[species].attribute_palette_variants[attribute].path`.
У некоторых партнёров, например Dragonoid и Hydranoid, все шесть исходных
палитр дают одинаковую иллюстрацию: она сохранена такой, как в файле.
Дополнительные палитры после первых шести не приписываются стихиям.

В крупных карточных файлах есть 213 числовых ресурсов: 0 — рубашка,
101–139, 201–232, 301–332, 401–432, 501–532, 601–633, 701–712 — карты.
Ещё шесть файлов — цветные рамки. Равное количество числовых ресурсов и
MES-записей позволяет сохранить **механическое** сопоставление сортировки с
подписями в `name_record`; статус прямо сообщает, что внутренние параметры
карточной системы пока не дизассемблировались. Пять `gate_art_matches`
дополнительно сверены по существующим названиям GateCatalog, видимым артам
и соответствующим исходным сообщениям. Эффекты MES только записаны как
данные: текущие правила и бонусы карт ими не заменяются.

## Воспроизведение извлечения и проверка

```bash
python3 tools/decode_ds_ui.py /path/to/raw \
  assets/ds/ui --manifest assets/ds/ui_manifest.json \
  --contact-dir /tmp/bakugan-ds-ui-contact
python3 tools/test_ds_ui_decoder.py -v
python3 tools/decode_ds_messages.py /path/to/raw assets/ds/messages.json
```

Двенадцать независимых примеров проверяют перекрывающиеся LZ10-ссылки,
отбрасывание повреждённых потоков, порядок RGB555, порядок полубайтов,
прозрачность, знаковые координаты и отражения NCE/NSC, индексы английских MES,
сохранение неизвестных управляющих кодов и отбрасывание неверных указателей.
Для фактического вывода отдельно проверены исходные SHA-256, загрузка PNG,
размеры 81 runtime-ресурса, 240 вариантов портретов и границы всех 1680 кадров:
ошибок нет. Точные количества проверенных файлов указаны в отчёте:
`builds/ds-ui-validation-0.10.json`. Эти проверки не являются запуском DS-игры
или Windows-сборки.

15 выбранных наборов пока пропущены: у части отсутствует собственная палитра,
у части ссылки указывают на цвета/тайлы вне локального файла. Возможно,
исходный движок загружает общие или динамические данные в VRAM; без
подтверждения они не подменяются подобранной палитрой. Полный список и причины
сохранены в `skipped` манифеста. Локализованные копии, уменьшенные дубликаты
карт и нерелевантные ресурсы редактора персонажа исключены из выбора.

Контактные листы подготовлены вне проекта в staging-каталоге
`/workspace/bakugan-ds-import/ui-contact`. Расположение элементов на итоговом
экране и переходы между этапами требуют отдельной сверки с DS-захватами;
одно декодирование изображений этого не подтверждает.
