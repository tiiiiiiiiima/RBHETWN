# Профилирование 0.22

Измерения собирает runtime_metrics.gd во время реальных матчей. Хранятся
ограниченные выборки времени кадра по фазам, p95/p99, максимум процессорного
времени кадра, статические выделения движка, видеопамять и количество узлов.
Встроенная диагностика записывает эти значения в отчёты каждой стадии.
Статические выделения Godot не являются RSS или рабочим набором процесса.
После прогона отдельно читается RSS/пик из /proc/self/status на Linux
или WorkingSet64/PeakWorkingSet64 через Get-Process на Windows.
Если системный счётчик недоступен, отчёт отмечает available=false.
Этот запрос выполняется после измерения кадров.

Базовый полный матч 0.21 завершён 3:1: main_ready 1584 мс, максимум
статических выделений около 125 МиБ. В aim/rolling/battle измерено
примерно 7.5–8.7 FPS, p95 около 135–145 мс. Среда: Linux, OpenGL 4.5,
Mesa llvmpipe, 1440×900, четыре потока программной графики, лимит 60 FPS.
Это программный рендеринг; результаты не описывают производительность
на Windows или отдельной видеокарте.

Исправления уменьшают ненужную работу скрытых аватаров и закрытой боевой
сцены, ограничивают кеш арен и частоту прогноза. Числа до/после зависят
от прогрева ресурсов и нагрузки окружения. Повторяемого роста FPS
в доступной программной графике пока не подтверждено; обещания 60 FPS нет.
Журналы и подробные измерения: builds/qa-0.22, full-suite-v2 и packaged-suite.
При оценке обычного ПК следует выполнить WINDOWS-QA-0.22.md.
